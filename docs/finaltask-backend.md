# Заявки: хранение, доставка и эксплуатация

Проверено локально 5 октября 2026 года. Этот документ описывает текущие
`public/api/lead.php`, `scripts/migrate-lead-state.php` и workflow `CI`.
Публикацию и проверку production фиксирует общий отчёт релиза отдельно.

## Где находится история

Обработчик PHP хранит состояние в `.designseichas-leads` рядом с **физическим**
корнем сайта: `dirname(__DIR__, 2) . '/.designseichas-leads'`, где `__DIR__` —
каталог установленного `api/lead.php`. Путь вне document root и вне каталога,
который заменяет `mirror --delete`. FTP-путь `DEPLOY_PATH=.` при chroot не меняет
расчёт PHP. Workflow пробует создать соседний каталог через FTP, но готовность
проверяет отдельным HTTP health-запросом после загрузки.

Абсолютный постоянный путь можно задать через `LEAD_STATE_DIR` в окружении PHP
или GitHub variable при генерации закрытого конфига. Непустое окружение имеет
приоритет над конфигом. Веб-корень, временные каталоги, относительные пути и
компоненты `.`/`..` запрещены. PHP должен иметь право создавать и записывать
этот каталог; ошибка доступа останавливает приём с 503 до отправки сообщений.

Каталоги имеют права `0700`; JSON истории, резервирования номеров и защищённый
конфиг — `0600`. Закрытый каталог содержит:

| Каталог       | Содержание                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| `deliveries/` | JSON версии 1: публичный номер, SHA-256 нормализованных полей заявки, время, подтверждения адресатов |
| `numbers/`    | Номер → SHA-256 внутреннего `submissionId`; постоянный реестр занятых номеров                        |
| `locks/`      | Межпроцессные блокировки заявок и ограничения частоты                                                |
| `rate/`       | Времена новых попыток по SHA-256 IP; максимум 5 новых заявок за 600 секунд                           |

Имена, телефоны, комментарии и полный текст заявки в этой истории не сохраняются.
Хеши и времена всё равно следует считать служебными данными с ограниченным
доступом. Автоматической очистки истории в коде нет: нельзя удалять `numbers/`
или `deliveries/` как временный кеш. Иначе пропадут гарантии сохранения номера
и распознавания уже подтверждённых отправлений.

## Номер и повторные запросы

Публичный номер состоит из 9 символов алфавита
`23456789ABCDEFGHJKMNPQRSTUVWXYZ`. Он создаётся через `random_int()` и атомарно
резервируется эксклюзивным созданием файла (`x+b`). При совпадении генерируется
новый кандидат, максимум 64 попытки. Номер, оставшийся после прерванной операции,
не освобождается и не выдаётся другому клиенту.

Для одного `submissionId` используется отдельный `flock`. JSON сначала полностью
записывается во временный файл того же каталога, затем заменяется через `rename`.
Используются `fflush`, а при PHP 8.1+ также `fsync` файла и каталога. PHP 7.4
поддерживается, но не даёт такой же защиты при аварийном отключении питания.
Корректность рассчитана на локальную файловую систему с работающими `flock`,
эксклюзивным созданием и атомарным `rename`.

| Сценарий                                                           | Результат                                                             |
| ------------------------------------------------------------------ | --------------------------------------------------------------------- |
| Оба адресата подтвердили доставку                                  | 200, `ok: true`, один номер в `leadNumber` и `requestId`              |
| Один или оба Telegram-запроса не подтверждены                      | 502, `delivery_failed`, выделенный номер сохранён                     |
| Повтор с теми же нормализованными данными                          | Тот же номер; отправка только ещё не подтверждённым адресатам         |
| Повтор уже полностью доставленной заявки                           | 200 с прежним номером, без новых отправлений                          |
| Те же `submissionId`, но другие данные                             | 409, `submission_conflict`                                            |
| Другая PHP-обработка того же ID ещё выполняется                    | 503, `submission_busy`, `Retry-After: 2`                              |
| Повреждённый JSON, утраченный реестр номера, недоступное хранилище | 503; история не сбрасывается и сообщения не пересылаются вслепую      |
| Лимит новых заявок по IP                                           | 429, `Retry-After: 600`; повтор существующей заявки остаётся доступен |

Обоим адресатам передаются одинаковые номер, дата, контактные поля, разрешённые
UTM, источник CTA, услуга/кейс и контекст калькулятора. Валюта ограничена RUB/BYN;
расчёт помечается как предварительный и не принимается за подтверждённую цену.
Текст ограничен 4096 символами с корректной обработкой UTF-8. У referrer удаляются
учётные данные, query и fragment; текущий клиент дополнительно ограничивает его
origin. Сервер проверяет согласие, типы и пределы полей независимо от клиента.

**Граница гарантии:** Telegram может принять сообщение, после чего сеть или PHP
прервётся до сохранения локального подтверждения. При повторе в этом окне
возможно второе сообщение с тем же номером. У `sendMessage` нет используемого
здесь ключа идемпотентности; обещать «ровно один раз» нельзя. Успех означает
подтверждение API обоих адресатов, а не прочтение человеком. Фоновой очереди
и автоматических повторов без повторного запроса клиента сейчас нет.

## Миграция прежней временной истории

Новый обработчик при повторе автоматически читает старую запись из
`sys_get_temp_dir()/design-seichas-<hash каталога api>`, сохраняя подтверждения.
Для полного переноса есть CLI-скрипт. Он не отправляет Telegram-сообщения,
присваивает публичный номер старым записям и не удаляет исходные файлы.

На сервере из checkout этого релиза (путь endpoint заменить фактическим,
если аккаунт использует другой физический document root):

```sh
php scripts/migrate-lead-state.php /www/designseichas.ru/api/lead.php
```

Если временный каталог CLI отличается от PHP-FPM или сайт перемещён, второй
аргумент должен указывать **старый фактический** каталог. Не вычислять его по
новому расположению endpoint:

```sh
php scripts/migrate-lead-state.php "$lead_endpoint" "$lead_legacy_directory"
```

Код 0 означает завершение (сообщение отдельно сообщает отсутствие старого
каталога), 2 — занятые записи, после завершения активных запросов нужен повтор,
1 — ошибка: сохранить оба каталога и проверить права/целостность. Успех команды
при отсутствующем неверно указанном старом каталоге не доказывает перенос.
На хостинге без SSH выполнить CLI через доступную панель/задачу хостинга либо
перенести каталог с помощью администратора. Публичного migration endpoint нет.

Старые сообщения уже отправлены без нового публичного номера: миграция не
редактирует их. При частичной старой доставке новый номер появится только в
недостающем сообщении. Не удалять временную историю до сверки и резервной копии.

## Резервная копия и откат

Резервировать весь закрытый каталог целиком, включая реестр номеров. Перед
согласованным снимком временно вернуть 503 на **POST** `/api/lead.php` на уровне
сервера и дождаться завершения PHP-запросов. Копирование во время записи может
снять подтверждения и резервирования на разных стадиях, хотя отдельные JSON
атомарны. Сайт и GET health можно оставить доступными.

Пример для серверной shell под владельцем файлов, после приостановки приёма:

```sh
lead_endpoint='/www/designseichas.ru/api/lead.php'
lead_state="$(php -r 'require $argv[1]; echo stateDirectory();' "$lead_endpoint")"
lead_backup_dir="$(dirname "$lead_state")/.designseichas-backups"
umask 077
mkdir -p "$lead_backup_dir"
chmod 700 "$lead_backup_dir"
lead_archive="$lead_backup_dir/leads-$(date -u +%Y%m%dT%H%M%SZ).tar.gz"
tar -czf "$lead_archive" -C "$(dirname "$lead_state")" "$(basename "$lead_state")"
chmod 600 "$lead_archive"
tar -tzf "$lead_archive" > /dev/null
```

После снимка вернуть приём, хранить копию вне document root и вне FTPS mirror,
переносить дополнительную зашифрованную копию за пределы этого сервера. Период
копирования и срок хранения задаёт владелец эксплуатации; расписание этим
релизом не создаётся. Проверять восстановление в изолированный закрытый каталог.

При откате фронтенда сохранить текущее хранилище и совместимый новый endpoint.
Возврат старого обработчика с временной историей потеряет связь с новыми
номерами. Для аварийного восстановления остановить приём, сначала скопировать
текущее повреждённое состояние, распаковать архив в отдельный приватный каталог,
проверить пары `deliveries`/`numbers`, права и владельца PHP, затем переключить
`LEAD_STATE_DIR` и выполнить health. Не накладывать архив поверх работающего
каталога. Восстановление устаревшей копии теряет более свежие подтверждения и
резервирования: требуется сверка сохранённых записей и Telegram до возобновления
приёма; гарантию отсутствия повторов в этом случае заявлять нельзя.

## Перенос на VPS

1. Развернуть статику и PHP-FPM с HTTPS. Секреты передать в окружение PHP-FPM
   или защищённый конфиг; не помещать их в клиентскую сборку/репозиторий.
2. Создать постоянный закрытый каталог, например
   `/var/lib/designseichas/leads`, владельцем которого является пользователь PHP.
   Задать его в `LEAD_STATE_DIR`. Подтвердить права и работу атомарных операций.
3. Приостановить POST на старом сервере, завершить активные запросы, перенести
   полную актуальную историю и при необходимости выполнить legacy-миграцию.
   Не запускать два независимых записывающих узла с разными копиями истории.
4. Проверить новый endpoint через health, закрытый конфиг и недоступность
   хранилища по HTTP. Проверку Telegram-учётных данных выполнять штатным
   read-only скриптом workflow; реальную тестовую заявку согласовать отдельно.
5. Переключить трафик, проверить health и формы без отправки реальных данных.
   Для отката после новых заявок сначала перенести обратно **актуальную** историю.
6. Настроить резервирование, мониторинг 5xx/health и дискового пространства.
   При необходимости очереди вынести получение заявки в транзакционное хранилище
   с уникальным ключом заявки и outbox; лимит Telegram exactly-once всё равно
   остаётся. При нескольких узлах файловый каталог заменить общим транзакционным
   хранилищем с уникальными ограничениями и блокировками.

`GET /api/lead.php?health=1` возвращает
`{"ok":true,"storage":"ready","recipients":2}` при готовности. Он проверяет
формат конфигурации двух разных адресатов и запись/удаление атомарного пробного
файла. Он **не** обращается в Telegram, не проверяет текущую доступность бота
и не раскрывает абсолютные пути или секреты. Workflow дополнительно проверяет
учётные данные до загрузки и завершает deploy ошибкой при неготовом health.
