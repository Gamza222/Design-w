## Проверки

Успешно: `npm run typecheck`, `npm run lint`, `npm run lint:fsd`, `npm test -- --maxWorkers=2` (20 suites / 87 tests), `npm run build` (66 маршрутов,0 ошибок аудита), `npm run e2e -- --workers=2 --reporter=line` (134 passed, Chromium+WebKit), PHP/HTTP/config/setup из [backend](finaltask-backend.md), Prettier изменённых файлов и `git diff --check`.

E2E изолирует ответы внешней карты Яндекса, сохраняя проверку её URL и разметки. Отправка форм в браузерных тестах перехватывается; серверная доставка проверяется отдельно с подменой Telegram. Внешние сервисы не являются частью гарантии этих тестов.

## Скорость

| Профиль | LCP до → после | CLS             | TBT            | Lighthouse | Передано      |

| mobile  | 6.16 → 4.44 с  | 0.0000 → 0.0000 | 50.5 → 32.0 мс | 63 → 76    | 1356 → 666 КБ |
| desktop | 1.52 → 1.15 с  | 0.0104 → 0.0032 | 0.0 → 7.5 мс   | 93 → 97    | 1921 → 850 КБ |

Lighthouse13.5.0, Chromium154, холодная production-страница через локальный gzip preview. До — изолированный коммит284d19a, после — итоговая сборка. Мобильный профиль:412×823,DPR1.75,RTT150мс,1,638Мбит/с,CPU×4; десктоп:RTT40мс,10,24Мбит/с,CPU×1. Один сопоставимый финальный прогон на профиль; это лабораторные наблюдения, не гарантия скорости всех устройств. Полевых INP/CrUX данных нет. Мобильный LCP улучшился, но остаётся выше целевого2,5с; дальнейшее ускорение требует отдельного профилирования после получения реального трафика. Небольшой рост desktop TBT с0 до7,5мс находится в низком диапазоне и не скрывается.

Основные устранённые причины: задержка прелоадера и opacity Hero, ранняя загрузка полноразмерных фоновых изображений, backdrop blur хедера, полноэкранный noise, скрытие текста до завершения анимации. Входные движения сохраняют читаемость при задержках кадров; reduced-motion отключает движение. Зависимости production не добавлены. Исходное видео сохранено с preload=none, фоновое видео не добавлялось.

Сырые сводки: [до](qa/performance-before.json), [после](qa/performance-after.json). Прокрутка1366×768 по4с в headless Chromium/WebKit на Mac; это автоматизация WebKit, а не ручная проверка Safari на физическом телефоне.

## Будущий VPS

1. Подготовить HTTPS-вебсервер с текущей статикой и PHP; сохранить домен, завершающие /,редиректы и404.
2. Создать приватный LEAD_STATE_DIR вне web root; перенести весь каталог states/numbers/locks/rate с владельцем PHP и правами0700/0600. Секреты перенести отдельно.
3. На время согласованного переключения остановить POST, сделать согласованную резервную копию, перенести финальный state, проверить health и изолированные сценарии доставки.
4. Проверить66 URL,SSL,robots/sitemap,формы/локали и аналитику; затем переключить DNS. Старый сервер сохранить для управляемого отката, исключив приём заявок одновременно двумя независимыми хранилищами.
5. Настроить резервирование, мониторинг health/ошибок и проверку восстановления. Детальные команды и ограничения — в backend-документе.
